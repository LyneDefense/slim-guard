# 移除执行预算与模型用量统计

## 范围

移除 Core/Harness、子 Agent、调用授权、营养/风格内部审查及离线风格训练的累计模型调用数、工具调用数、Token 预算及拦截逻辑。删除旧预算类，不保留失效配置开关。

以下约束不是累计成本预算，仍保留：权限和工具授权、单请求最大输出长度、上下文大小、超时、取消、有限格式修复与语义返工、风格优化轮数。Core 模型—工具循环不再因累计调用数或 Token 提前结束，可能消耗更多时间和费用。

## 记账口径

- 最小账目是一笔实际模型请求，不是 Agent 汇总结果。父调用不得重复计入子调用 Token。
- 用户一条输入及该轮所有系统消息、教练消息、卡片合为一次问答，以 Turn ID 关联；追问后的用户回答是新问答。
- 请求失败前已创建的 Turn 仍在列表中；移动端创建 Turn 前失败的请求也保留。没有采集记录显示“未记录调用”，不推断历史用量为零。
- 主动提醒标记其触发类型，不伪装成用户问答。
- 后台记忆提取通过任务中可信的 user_id / turn_id 回填原问答。任务无用户归属时展示在“系统任务”，不归给管理员或最近聊天用户。
- 请求 ID、Turn ID、Agent 角色、Invocation ID、父 Invocation ID、工具调用 ID、任务 ID、组件、用途、模型、服务商请求 ID、耗时和请求状态均可记录。
- 输入、输出、总 Token 与缓存输入 Token 按服务商实际字段保存；缺失为 NULL。输入与输出均已知时可相加得出总数。没有服务商数据不按文本长度估算、不填 0。
- 一个 Agent Invocation 可以包含多次请求（生成、内部审查、失败重试）。Agent 总量只加该角色自己的实际请求。详情页同时显示审计记录中的实际执行次数，包括未发起模型请求的执行。
- 列表的 Invocation 数表示有模型请求的 Invocation；详情页“Agent 执行”包含无模型调用的执行。两者不要混同。
- 请求状态表示模型接口请求结果，不等同于工具执行成功、回复语义合格或用户已收消息。业务结果仍查看原 Trace。
- 取消、超时、结构解析失败的请求仍记账；模型已返回 usage 的失败请求保留用量；无返回则未知。内部语义校验失败后的新请求另记一笔。

## 接入位置

统一模型/视觉 Gateway 装饰器覆盖 Core、聊天、营养、风格改写、共享审查、回复审查、记忆召回、记忆提取和风格训练。Embedding / Rerank 在实际请求边界单独记账。RAG 入库与评测按独立任务关联。

组件归属与 Agent 归属不是同一维度。例如营养 Agent 内部的检索/重排仍记录组件和工具身份；不冒充新 Agent。独立记忆提取、离线资料入库没有 Agent 归属。

已知覆盖边界：外部 Mem0 服务内部模型消耗没有回传到本应用，当前无法纳入 Token 总量，界面明确提示。历史未记录的调用无法补出精确 usage。账本写入异常不改变业务结果，但会记录 `model_usage_write_failed` 和 call_id；异常期间总量可能不完整。进程崩溃留下 running 行，不能当作成功或零消耗。

## 后台

左侧“模型用量” → 用户汇总 / 无用户归属的系统任务；用户详情“问答用量” → 问答列表 → Agent 汇总、组件分项和逐次模型请求。问答详情可跳转原 Trace 查看输入与实际回复。

用户汇总按调用发生时间筛选；问答列表按问答开始时间筛选，并汇总该问答后续关联调用。界面有分页、时区明确的时间筛选、未知用量计数及失败请求计数。所有接口沿用管理员登录校验，详情查询同时限定用户和问答。
