# 模型请求网络重试

## 范围

本次只实现文本/图片模型请求层的临时故障恢复，不改变 Core 的业务调度，不重跑 Turn 或已完成的业务工具，不修改 `loop.py` 中现有的工具失败策略。

接入：Core、共享同一模型网关的专业/聊天/风格/审查调用、记忆召回、后台记忆提取、风格训练和 RAG 可回答性判断，以及图片识别。

不扩展到独立的 Embedding、Rerank、外部 Mem0 服务 HTTP 请求或业务工具重试。

## 分层

```text
调用方
  → RetryingModelGateway / RetryingVisionGateway
    → MeasuredModelGateway / MeasuredVisionGateway（每次尝试独立记录）
      → 原始模型 Provider（发送一次请求）
```

- `agent_models/retry.py`：有限尝试、退避、取消传播、Retry-After 解析及文本/图片适配。
- `agent_models/assembly.py`：统一装配顺序，避免把多次实际请求合成一条用量记录。
- `agent_models/errors.py`：Provider 错误可携带等待时间。
- `agent_models/zhipu.py`、`zhipu_vision.py`：读取 Retry-After；错误响应若确实返回用量，也保留用量。
- `agent/composition.py`、`main.py`：现有模型调用入口改用统一装配。用量表及后台查询不变。

## 策略

- 默认最多 3 次尝试（首次 + 2 次重试），仅是单个网络请求的恢复上限，不是 Agent/Turn/Token 预算。
- 重试：模型超时、传输错误、HTTP 408/429/500/502/503/504。
- 不重试：其他 HTTP 错误（包括鉴权、参数错误）、响应格式错误、不支持的模型功能、程序异常。
- 退避默认约 1 秒、2 秒，附加最多 25% 抖动；每次等待上限 30 秒。
- 服务端 Retry-After 较大时按其要求等待；超过 30 秒则停止本层重试并抛出错误，不擅自提前请求。
- 取消及调用方的外层超时原样传播，包括退避等待期间。单次 HTTP 超时仍使用原配置。
- 每次尝试使用同一个请求对象，不改变消息、参数、工具定义，不重新调用此前业务工具。
- 用完尝试次数后抛出最后一次原异常，由现有调用方处理，不合成业务回复。

## 用量及边界

- 每次尝试单独保存状态、耗时和原有用户/Turn/Agent/Invocation 归属。
- 没有收到供应商用量时保留 NULL，后台统计为未知；收到失败响应的真实用量也计入。
- Core Loop 的响应列表仍只含成功返回的模型响应；实际请求次数及所有已知 Token 总量以用量账本为准。
- 读超时不代表供应商没有执行，重试可能带来额外费用，无法通过本地代码保证模型请求只计费一次。未返回用量不能估算成零。
- 不新增配置项、数据库迁移或前端改动；本次未部署。

## 验证重点

- 文本和图片：超时 → 429 → 成功，独立三条账，原请求不变。
- 永久错误不重试；响应格式错误仍记录真实 Token，不作为网络问题重试。
- 耗尽尝试次数、Retry-After、请求中取消、退避中取消。
- 工具写入成功后模型超时：只重发模型请求，工具执行一次。
- 数据库聚合验证：按用户、Turn、Agent 统计全部尝试；未知用量独立计数，用户隔离。

验证结果（2026-09-23）：

- 模型网关、用量、Harness、Runtime、回复模块、移动端 API 和回调链路的定向回归：163 项通过，2 条已有的 HTTP 413 常量弃用警告。
- 补充网关边界测试及记忆提取、RAG 可回答性测试：40 项通过（与上一轮部分重叠，不应相加作为独立用例数）。
- Ruff、Mypy、改动文件格式检查、差异检查及 5 个模块独立进程导入检查通过。
- 使用模拟 HTTP/模型及本地数据库，没有调用真实模型或变更服务器。
